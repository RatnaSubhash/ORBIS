[Heading 1] ABSTRACT

[Normal] Modern desktop operating systems provide search utilities, recent-file lists, application launchers and voice assistants; however, these facilities generally operate at the level of isolated commands or individual resources. They rarely maintain a structured understanding of what a user was actually trying to accomplish across several applications, documents, browser resources and intermediate actions. Consequently, after a shutdown, crash, interruption or task switch, users must manually reconstruct their working state by reopening applications, finding relevant documents, recovering browser resources and remembering the unfinished objective. This repeated reconstruction introduces avoidable cognitive and temporal overhead.

[Normal] ORBIS is proposed as a privacy-preserving AI workspace continuity system that addresses this problem through a Context Reconstruction Engine (CRE). Instead of representing a session as a list of files, ORBIS models a work session as Context DNA containing user intent, active applications, relevant files, browser resources, temporal information and semantic relationships. These Context DNA records are connected through a Workspace Knowledge Graph so that resources can be retrieved not only by exact keywords but also through their semantic and relational proximity to a task. A semantic retrieval layer uses embeddings and vector similarity search, while a hybrid ranking strategy incorporates recency, project association and graph relationships.

[Normal] An Intent Continuity Engine (ICE) extends the system from retrospective retrieval to proactive assistance. Given a reconstructed session, ICE estimates likely next activities and presents ranked recommendations for the user. Where restoration is requested, a controlled automation layer can reopen permitted applications and resources, subject to availability checks, privacy policies and human approval for consequential operations. Voice and natural-language interaction provide an accessible interface, while local-first processing using components such as SQLite, FAISS, Sentence Transformers, Whisper and Ollama is intended to minimize unnecessary transmission of personal workspace data.

[Normal] The research contribution is therefore not the invention of an individual embedding model, database or language model. The contribution lies in the system-level integration of context reconstruction, graph-based workspace memory, semantic retrieval, intent continuity and privacy-preserving restoration, together with a purpose-built evaluation framework for interrupted-workspace recovery.

[Normal] Keywords—Context-aware computing; semantic search; workspace memory; desktop assistant; natural language processing; knowledge graph; intent prediction; desktop automation; privacy-preserving AI.

[Heading 1] I. INTRODUCTION AND PROBLEM STATEMENT

[Normal] Contemporary knowledge work is inherently multi-application. A single task may involve an IDE, terminal, browser, PDF viewer, spreadsheet, presentation software, file manager, notes and communication tools. The user therefore creates a distributed workspace state in which the meaning of one resource often depends on several other resources. A source-code file may be related to a debugging page, a terminal log, a design document and a project folder. A filename-based search system can retrieve the file but cannot reliably reconstruct the task-level context in which it was being used.

[Normal] Existing mechanisms also provide incomplete continuity. Recent-file lists remember individual artifacts, browser history remembers visited pages, and application session restoration may reopen windows. However, these mechanisms are fragmented and generally do not answer the higher-level question: 'What was I doing, what resources were related to it, and what should I resume next?' The gap becomes more pronounced when the user works across application boundaries or when an interruption occurs before the task is completed.

[Normal] Problem formulation:

[List Bullet] How can heterogeneous workspace observations be converted into a unified representation of user task context?

[List Bullet] How can a system retrieve relevant prior context when the user describes an unfinished task semantically rather than by exact filenames?

[List Bullet] How can relationships among applications, files, browser resources, projects and sessions be represented so that retrieval is context-sensitive?

[List Bullet] How can the system infer a likely next activity without making overconfident assumptions about user intent?

[List Bullet] How can an interrupted workspace be restored automatically while respecting user privacy, permissions and application-state uncertainty?

[List Bullet] How can the effectiveness of workspace continuity be evaluated using objective retrieval, reconstruction, prediction, latency and user-effort metrics?

[Normal] Let a workspace session be S = {A, F, B, E, I, R}, where A is the set of applications, F the set of files/documents, B browser resources, E interaction/event information, I the inferred user intent and R the relationships among these entities. ORBIS constructs a structured representation C(S), called Context DNA, and attempts to retrieve or reconstruct the most relevant session S* given a query q or interruption event. The target is to maximize contextual relevance and restoration completeness subject to privacy, safety and latency constraints.

[Heading 1] II. MOTIVATION

[Normal] The motivation is rooted in the long-standing idea that computers should augment human memory and problem solving. Bush's Memex envisioned associative access to accumulated information; Licklider proposed man-computer symbiosis; Engelbart developed the concept of augmenting human intellect. These ideas are particularly relevant to modern desktop work because today's users generate much richer digital traces than the systems that inspired those visions. [1 - 3]

[Normal] At the same time, interruptions are a practical productivity problem. Users frequently suspend a task for meetings, messages, system updates, unrelated questions or device shutdowns. After the interruption, the cost is not merely reopening a window: the user must reconstruct the mental and digital state of the task. Research on interruption has shown that interrupted work can involve increased stress, frustration and effort, which motivates tools that preserve actionable context. [8][9]

[Normal] AI provides an opportunity to move beyond passive storage. Semantic embeddings allow the system to match a natural-language description to related resources; knowledge graphs provide explicit relationships; language models can summarize and interpret context; and controlled automation can turn a retrieved context into a restored workspace. The central motivation of ORBIS is to combine these capabilities around continuity rather than around generic chat or isolated command execution. [10 - 20]

[Heading 2] 2.1 Practical motivation

[List Bullet] Reduce time spent reopening applications and rediscovering task resources.

[List Bullet] Reduce cognitive load caused by reconstructing unfinished work from memory.

[List Bullet] Enable semantic queries such as 'restore the work I was doing on the routing project yesterday'.

[List Bullet] Preserve relationships between resources rather than storing isolated search results.

[List Bullet] Support proactive but explainable recommendations for the next likely action.

[List Bullet] Keep sensitive workspace information local by default.

[List Bullet] Provide an academically measurable problem with clear baselines and ablation experiments.

[Heading 1] III. LITERATURE SURVEY

[Normal] The literature relevant to ORBIS can be organized into six themes: personal information management and digital memory; context-aware computing; semantic language representation and retrieval; knowledge graphs; agent memory and tool use; and computer-use/desktop automation with safety. This organization is intentionally broader than a simple list of AI models because ORBIS is a systems problem that combines HCI, information retrieval, representation learning and automation.

[Heading 2] 3.1 Personal information management and digital memory

[Normal] Bush (1945) introduced the Memex as a conceptual system for associative information storage and retrieval. Licklider (1960) and Engelbart (1962) extended the broader vision of computers as partners in human intellectual work. MyLifeBits (Gemmell et al., 2002; 2006) demonstrated a practical personal digital archive and explored search and organization of large quantities of personal information. Stuff I've Seen (Dumais et al., 2003) addressed retrieval of information previously encountered across multiple sources. These works establish that personal digital memory is valuable, but they primarily focus on remembering and retrieving information. ORBIS extends the problem toward reconstructing a task-oriented workspace and restoring the operational state surrounding that information. [1 - 3][6][7]

[Heading 2] 3.2 Context-aware computing and interruptions

[Normal] Dey, Abowd and Salber developed a conceptual framework for context-aware applications, while the Context Toolkit provided reusable mechanisms for acquiring and distributing context. This literature demonstrates that context should be represented explicitly rather than inferred independently by each application. Interruption studies by Czerwinski et al. and Mark et al. demonstrate that relevance, timing and task switching influence productivity and stress. ORBIS treats desktop state itself as context and introduces a session-level representation that combines temporal, semantic and relational signals. [4][5][8][9]

[Heading 2] 3.3 Semantic representations and retrieval

[Normal] Word2Vec and Paragraph Vector demonstrated distributed representations for words and documents. Transformer-based representations, especially BERT, improved contextual language understanding. Sentence-BERT made semantic similarity practical by generating embeddings that can be compared efficiently. Dense Passage Retrieval, ColBERT and BEIR demonstrate the importance of semantic retrieval and strong evaluation methodology. ORBIS applies these ideas to a private heterogeneous corpus containing files, applications, browser resources and session summaries rather than public passages alone. [10 - 14][18 - 20]

[Heading 2] 3.4 Vector search and knowledge graphs

[Normal] FAISS and approximate nearest-neighbor methods such as HNSW enable efficient vector retrieval at scale. Knowledge-graph research provides mechanisms for representing entities and relationships, while TransE, DeepWalk and node2vec demonstrate graph representation learning. ORBIS combines vector retrieval with an explicit Workspace Knowledge Graph because semantic similarity alone cannot always capture relationships such as 'these two files were used in the same debugging session' or 'this browser resource supported this project'. [15][16][21 - 25]

[Heading 2] 3.5 Agent memory, reasoning and tool use

[Normal] ReAct interleaves reasoning and action, Toolformer studies tool invocation, Reflexion introduces feedback through verbal self-critique, and Generative Agents demonstrate retrieval and reflection over stored memories. MemGPT explores hierarchical memory management for long contexts. These systems suggest that persistent memory and tool access can substantially extend language-model capabilities. ORBIS borrows the architectural principle of persistent memory but specializes it for local desktop workspace continuity. [27 - 32]

[Heading 2] 3.6 GUI agents, desktop automation and safety

[Normal] WebArena, Mind2Web, VisualWebArena and WebVoyager demonstrate increasingly realistic browser-agent evaluation. OSWorld, Windows Agent Arena and related computer-use benchmarks expose the difficulty of reliable long-horizon desktop interaction. CogAgent, AppAgent and UFO explore GUI grounding on desktop or mobile surfaces. RPA research highlights brittleness under interface change, while work on indirect prompt injection shows that content an agent reads can influence later actions. ORBIS therefore treats automation as a controlled downstream capability rather than the sole definition of intelligence, with explicit policy checks and human approval for consequential actions. [33 - 40]

[Heading 1] V. OBJECTIVES

[Normal] 1. To design and implement a Context Reconstruction Engine that transforms heterogeneous desktop observations into structured Context DNA.

[Normal] 2. To construct a Workspace Knowledge Graph representing relationships among sessions, projects, tasks, applications, files and browser resources.

[Normal] 3. To implement semantic retrieval using Sentence Transformers and FAISS for natural-language workspace queries.

[Normal] 4. To develop a hybrid ranking mechanism combining semantic similarity, lexical overlap, temporal recency, project relevance and graph proximity.

[Normal] 5. To develop the Intent Continuity Engine for next-action prediction and context-aware recommendations.

[Normal] 6. To provide natural-language and voice interaction for searching, restoring and querying workspace context.

[Normal] 7. To design a privacy-first local processing architecture using local storage and local inference wherever practical.

[Normal] 8. To implement a controlled desktop restoration layer that validates resources before reopening them.

[Normal] 9. To enforce permission policies and human confirmation for high-impact or irreversible operations.

[Normal] 10. To create a synthetic and consent-based dataset capable of measuring retrieval, reconstruction, prediction, restoration and latency.

[Normal] 11. To compare the complete system with keyword, metadata-only and vector-only baselines.

[Normal] 12. To evaluate the effect of individual components through ablation studies.

[Heading 1] VI. DESIGN METHODOLOGY

[Normal] The design follows a requirements-first, top-down methodology inspired by the reference batch report. The system boundary is first defined from the user's perspective, then use cases are mapped to components, the end-to-end data flow is modelled, and finally the implementation is decomposed into independently testable modules. Unlike the reference system, whose primary flow begins with a hotkey and a spoken command, ORBIS begins with workspace observation and session reconstruction because continuity is the central research problem. [4][5][21][22][25]

[Heading 2] 6.1 Requirement elicitation and use-case modelling

[Normal] Fig. 1. UML use-case model of the ORBIS workspace continuity system

[Normal] The primary actor is the desktop user. Core use cases include capturing workspace context, issuing natural-language queries, searching related resources, restoring a previous workspace, receiving next-action recommendations, approving automation, excluding private data and inspecting context/audit history. The use-case model establishes that the user remains the final authority over what information is observed and what consequential action is executed.

[Heading 2] 6.2 Component mapping

[Normal] The use cases are mapped into five major architectural concerns: interaction, context acquisition, intelligence, memory/knowledge, and action/safety. Each concern is further decomposed into modules with a single primary responsibility. This separation allows the retrieval subsystem to be evaluated independently from automation, and the intent engine to be evaluated independently from the UI.

[Heading 2] 6.3 Workflow modelling

[Normal] The workflow models both continuous observation and on-demand restoration. Context acquisition may run periodically or on relevant workspace changes. When a user asks for restoration, the system identifies candidate sessions, retrieves associated resources, checks their current availability, ranks the restoration plan and executes only approved actions. Feedback from successful or failed restoration is written back into the session store to improve later recommendations.

[Heading 1] VI-A. DETAILED DESIGN METHODOLOGY

[Heading 2] 6.1.1 Workspace observation

[Normal] Collect user-authorized metadata about active applications, window titles, file paths or hashes, browser tabs, recent events, project folders and selected interaction signals. The system should minimize capture by using metadata when sufficient and should support exclusion rules for folders, applications and resource types. [4][5]

[Heading 2] 6.1.2 Session segmentation

[Normal] Group low-level events into coherent work sessions using temporal proximity, application continuity, project association and semantic similarity. A simple initial rule-based segmenter can start a new session after prolonged inactivity or a strong task/context transition. [5][8][9][20]

[Heading 2] 6.1.3 Content and metadata extraction

[Normal] Extract permitted text from documents and source code; derive file type, modification time, project association and content fingerprints. OCR using EasyOCR/OpenCV may process screenshots or image-based content only when explicitly allowed.

[Heading 2] 6.1.4 Intent extraction

[Normal] Use the local NLP/LLM layer to generate a compact intent summary such as 'debug routing simulation and compare packet-loss results'. The summary becomes a searchable semantic representation rather than a raw activity log.

[Heading 2] 6.1.5 Context DNA construction

[Normal] Construct a structured record containing session identity, time interval, inferred intent, applications, resources, entities, temporal features, semantic embeddings, confidence and privacy policy. Context DNA is the primary unit for cross-session retrieval. [4][5][21]

[Heading 2] 6.1.6 Workspace Knowledge Graph construction

[Normal] Create nodes for users, sessions, projects, tasks, files, applications, browser resources and events. Create typed edges such as contains, used_in, opened, related_to, followed_by, modified_during and supports_task. [21 - 25]

[Heading 2] 6.1.7 Semantic indexing

[Normal] Generate embeddings for Context DNA summaries and resource descriptions. Store vectors in FAISS. Maintain metadata pointers to SQLite records so retrieval can return complete context rather than an embedding alone. [14 - 20]

[Heading 2] 6.1.8 Hybrid retrieval and ranking

[Normal] Retrieve top-k semantic candidates, then rerank using lexical overlap, recency, project match, application continuity and graph proximity. A conceptual score is Score = w_s S_semantic + w_r S_recency + w_p S_project + w_g S_graph + w_l S_lexical, with weights tuned on validation data. [14 - 20]

[Heading 2] 6.1.9 Intent Continuity Engine

[Normal] Use recent context, historical session sequences and retrieved relationships to rank possible next activities. Initial implementation should prefer interpretable rules or lightweight classifiers; later experiments may compare sequence models. [28 - 32]

[Heading 2] 6.1.10 Restoration planning

[Normal] Convert the target session into an ordered restoration plan. Check whether each application/resource still exists, whether paths changed, whether browser resources are accessible and whether the action is permitted.

[Heading 2] 6.1.11 Safe execution

[Normal] Execute only allowlisted, reversible or user-approved actions. High-impact actions should trigger an approval gate that displays the planned action and expected consequence before execution. [27][28][30][40]

[Heading 2] 6.1.12 Feedback and audit

[Normal] Store success/failure, unavailable-resource events and user corrections. These records are used for later analysis and can support self-correction without silently changing policy boundaries.

[Heading 1] IX. CONTEXT DNA REPRESENTATIONS

[Normal] Context DNA is the principal proposed representation of ORBIS. It is deliberately richer than a vector embedding because embeddings alone cannot express every operational property needed for restoration. A Context DNA record should contain both machine-readable fields and a semantic summary.


--- TABLE (11 rows x 3 cols) ---
Row 0: Field Group | Representative fields | Purpose
Row 1: Identity | session_id, user_id_hash, project_id, task_id | Uniquely identifies the session without exposing raw identity in benchmark data.
Row 2: Temporal | start_time, end_time, last_active_time, interruption_time | Supports recency and interruption analysis.

[Heading 1] XI. SEMANTIC RETRIEVAL AND HYBRID RANKING

[Normal] ORBIS should not depend on a single retrieval signal. Keyword matching is useful for exact names, embeddings are useful for semantic descriptions, graph traversal is useful for relationships, and recency is useful for temporal relevance. The proposed retrieval pipeline therefore uses a multi-stage approach. [10 - 20]

[List Bullet] Stage A — Candidate generation: encode the natural-language query and retrieve top-k Context DNA/resource embeddings from FAISS.

[List Bullet] Stage B — Lexical augmentation: search exact project names, filenames, domains and salient terms.

[List Bullet] Stage C — Graph expansion: include related sessions, files and projects connected to high-scoring candidates.

[List Bullet] Stage D — Temporal filtering: apply a recency prior when the query contains time expressions or when recent sessions are strongly relevant.

[List Bullet] Stage E — Hybrid reranking: combine semantic similarity, lexical score, graph proximity, project match and recency.

[List Bullet] Stage F — Diversity control: avoid returning ten near-duplicate resources from the same session when multiple independent resources could improve coverage.

[Normal] A possible ranking formulation is: R(d|q) = w_s·Sim(q,d) + w_l·Lex(q,d) + w_g·Graph(q,d) + w_r·Recency(d) + w_p·ProjectMatch(q,d). The weights should be learned or tuned using a validation set rather than presented as universal constants. An ablation study will measure the effect of removing each signal.

[Heading 1] XII. INTENT CONTINUITY ENGINE (ICE)

[Normal] ICE is the component that differentiates ORBIS from a passive search utility. Its task is to estimate what the user is likely to do next based on the reconstructed context. For example, if the last session contained a source-code edit, a debugging log and a browser search for an error message, ICE may rank 'continue debugging', 'reopen the error log' or 'open the relevant documentation' as candidate actions. [28 - 32]

[Heading 2] 12.1 Initial ICE strategy

[List Bullet] Extract the current session intent and unresolved task entities.

[List Bullet] Retrieve similar previous sessions.

[List Bullet] Identify the last completed and last incomplete actions.

[List Bullet] Construct candidate next actions from observed transitions.

[List Bullet] Score candidates using recency, frequency, task similarity and session continuity.

[List Bullet] Return top-k recommendations with confidence and a short explanation.

[Heading 2] 12.2 Advanced ICE strategy

[Normal] If sufficient training data becomes available, the rule-based ranker can be compared with a supervised classifier or sequence model. The research evaluation should focus on whether added model complexity improves Top-1/Top-3 prediction enough to justify additional compute and latency. [28 - 31]

[Heading 1] XXII. CONCLUSION AND FUTURE SCOPE

[Normal] ORBIS addresses a specific weakness in current desktop interaction: computers can remember fragments of activity, but they do not consistently reconstruct the task-level context that gives those fragments meaning. The literature demonstrates strong foundations for each component—personal digital memory, context-aware computing, semantic retrieval, graph representations, language-model reasoning, speech recognition and computer-use automation—yet these strands are usually evaluated independently. [1][4][10][21][28][33][38][40]

[Normal] The proposed system closes this integration gap by representing each work session as Context DNA, connecting sessions and resources through a Workspace Knowledge Graph, retrieving context through semantic and hybrid search, predicting next activities through the Intent Continuity Engine, and translating a selected context into a privacy-preserving restoration plan. The system deliberately treats automation as a controlled capability rather than unrestricted autonomy.

[Normal] For Review-1, the project should be presented as a research-backed systems design with a measurable hypothesis: a context-rich, graph-aware and semantically retrievable representation of desktop work can reduce the effort required to resume interrupted tasks. The final implementation and evaluation should determine how much each component contributes, rather than assuming that adding more AI automatically makes the system better—which, as usual, is where engineering reality ruins the marketing slide.
