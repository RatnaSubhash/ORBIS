# ORBIS REVIEW-2: END-TO-END (E2E) PIPELINE VERIFICATION EVIDENCE

**Document Reference:** `docs/review2_e2e_evidence.md`  
**Evaluation Standard:** Full-Stack Pipeline Traceability:  
`React / Electron UI` $\longrightarrow$ `Frontend Service Layer` $\longrightarrow$ `FastAPI Gateway REST/WebSocket` $\longrightarrow$ `Agent Orchestrator` $\longrightarrow$ `Hierarchical DAG Planner` $\longrightarrow$ `Safety & Policy Validator` $\longrightarrow$ `Tool Execution` $\longrightarrow$ `Independent Verification` $\longrightarrow$ `Physical File / OS State Result`.  
**Strict Rule:** Pure unit test results (isolated function calls or mocks) are **excluded** from this document. Only verified, integrated executions through the active pipeline are recorded.

## 1. End-to-End Pipeline Architecture Definition

Every verified E2E capability in this document traverses the complete multi-tier runtime:

```mermaid
sequenceDiagram
    autonumber
    actor User as Desktop User
    participant UI as Electron / React Client
    participant GW as FastAPI Gateway (:8000)
    participant Orch as Agent Orchestrator
    participant Plan as Hierarchical Planner
    participant Safe as Preflight / Policy Guard
    participant Tool as Tool Execution Sandbox
    participant OS as Windows OS / Filesystem

    User->>UI: Submits natural-language prompt or action
    UI->>GW: POST /api/tasks or WebSocket connection
    GW->>Orch: Injects task with ExecutionContext
    Orch->>Plan: Classifies intent & generates DAG plan
    Plan->>Safe: Preflight validation & RiskLevel evaluation
    alt RiskLevel == HIGH
        Safe-->>UI: Emits PENDING_APPROVAL modal
        User->>UI: Authorizes execution (POST /api/tasks/{id}/approval)
        UI->>GW: Resumes execution pipeline
    end
    Safe->>Tool: Dispatches parameters to BaseTool
    Tool->>OS: Executes Win32 API, subprocess, or file write
    OS-->>Tool: Raw return code / file descriptor / handle
    Tool->>Safe: Calls verify(params, result, context)
    Safe-->>Orch: Returns VerificationReport
    Orch-->>GW: Broadcasts live event tokens over WebSocket
    GW-->>UI: Updates LiveFlow / Command bubble with grounded result
```
